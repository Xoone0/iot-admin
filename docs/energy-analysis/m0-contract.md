# M0 基础契约与 M1-A 实施范围

适用基线为 `dev @ 2563cd367bcd333d85a650f1be441f3f9589dcaa`、[现状审计](current-state.md)、[差距矩阵](feature-gap-matrix.md)、[P0 实施计划](p0-implementation-plan.md)及《建筑能耗监测分析模块 PRD V1.0》§9–13。下列接口是本模块消费方契约。项目/目录/身份服务的实际绑定由平台负责人确认，现阶段在 Go 测试中使用替身。

## 标识、所有者和有效期

| 对象 | 稳定标识 | 建议权威所有者与约束 |
| --- | --- | --- |
| 租户和项目 | `(tenant_id, project_id)` | 平台项目目录。ID 视为不透明字符串，项目目录提供项目 IANA 时区、版本、有效期和来源。 |
| 建筑、楼层和空间 | `(tenant_id, project_id, object_kind, object_id)` | 建筑/空间目录。楼层、区域均以空间节点表达，可追溯建筑和父节点。关系变更产生新版本。 |
| 组织/科室 | 同一对象键，类型为 `organization` | 组织目录。组织树独立于空间树。人员/组织变更不覆盖历史版本。 |
| 计量点 | `(tenant_id, project_id, terminal_id, item_code)` | 设备接入负责终端和物模型。现有 `terminal.id` 唯一关联 `terminal.type_id`，属性按 `(type_id, item_code)` 匹配。能耗维护经核验的项目归属、量测口径及版本。设备型号或物理表更换须留历史。 |
| 归属/统计边界 | 点位键与建筑、空间、组织、分项及边界的版本化关联 | 能耗负责映射，目录所有者及接入负责人核对其来源。多个统计视角分开维护。 |

所有版本采用 `[生效时间, 失效时间)`，空失效时间表示开放区间。M0 范围解析及 M1-A 单次计算需能由一个项目/对象/点位口径版本覆盖请求范围，跨版本由调用方分段并保留版本。累计端点恰等于版本结束时可参与该版本的最后一段，仅当端点和左端属于同一明确表码代次且仍使用该版本的表码语义。只有下一代次的端点时保留断段。网关、数据域、显示名称只作描述。 [终端与属性结构](../../migrations/0001_datasource.sql#L16)

## 可信身份与范围

- `IdentitySource` 从经平台验证的上下文提供主体签发方与稳定主体 ID。`AccessPolicy` 依据主体、动作、项目、对象/点位和整个查询范围裁定访问。项目键由调用方选择，是否有权由平台证明。未来传输层适配器须验证会话/签名及信任边界，客户端参数、任意头或网关接入凭证无主体证明效力。
- `ResolveScope` 在查目录之前鉴别主体并授权整个请求。缺失适配器、无主体或拒绝均失败关闭。目录记录必须匹配键并覆盖范围。配置、报表任务和下载使用各自动作，导出和下载时重新确认范围。未来来源适配器在授权范围内取点，完整总量或差额要求完整统计边界的权限。
- 当前管理端拦截器默认放行，且基线无已验证的项目对象权限服务。本模块契约暂时不挂正式入口。 [当前鉴权](../../internal/admin/auth.go) · [服务入口](../../cmd/server/main.go#L127)

## 量测、单位与质量

| 类型 | 输入与计算 |
| --- | --- |
| 累计量 | 已确认的累计点位、原单位、有效倍率、表码代次、事件时刻与原始记录引用。相邻有效端点相减，乘倍率与物理单位换算系数。跨复位/换表代次保留断段。已确认发生一次回卷时用 `量程模数 - 左表码 + 右表码`，无有效量程或出现未确认负跳时待核查。 |
| 区间量 | 接收明确的起止、数量与原始引用，按点位采样周期对齐后直接转换。适配器应将已应用倍率的来源显式配置为倍率 1。跨桶、重叠或口径未知的区间交由上游规范化。 |
| 瞬时量 | 点位可在契约中分类，计算拒绝瞬时通道。电压、电流、瞬时功率等仍由原模块负责。 |

物理单位白名单由计算层按能源校验。电量归一为 kWh，水为 m³，明确基准条件的燃气为 Nm³，冷/热/蒸汽热量为 GJ。仓库单位使用前须经接入侧核对。煤当量单独计算，只接受项目同边界、同时间和同数据截面的分类结果以及适用、经审批的 kgce 系数版本。水单列。覆盖不全或任一能源缺少有效系数时保留各分类值，综合值为空。跨单位直接相加无效。

记录携带事件时间、来源能见时间、源系统与稳定记录 ID。RAW 的事件时间候选为 `value_time`，能见时间由来源确认，现有 `received_at` 是候选，RAW 引用须包含分区键 `(id, received_at)`。快照是分段样本，只有事件时间和意义满足端点契约时才使用。优先接入经确认的区间量，单次计算只取同一来源口径。 [RAW 结构](../../migrations/0024_raw_ingest.sql#L23)

同一时刻或区间的相同值与语义合并，保留全部不同来源引用。不同值、质量、代次或回卷标记冲突时该点位区间待核查。晚到数据按事件时间落桶，`as_of` 控制可见版本，后续重算只改变受影响区间。重跑固定截面时，计算结果和引用次序一致。上游如果允许替换冲突记录，须提供经过审批且可按截面读取的有效版本。审批后的手动/修正可参与统计并保留质量。估算保留质量与证据，本轮不计入有效用量。用量为 nil 表示没有有效区间，已知零为数值 0。覆盖率 = 有效区间数 / 期望区间数，缺测与待核查单列。

## 项目时间与同期

时间戳为带偏移的绝对时刻，归桶时显式加载项目 IANA 时区。统计窗口为 `[from,to)`，累计计算允许读取等于 `to` 的右端点。时、日、月均按项目当地边界切分，日/月聚合使用完整自然桶。采样周期本轮为整分钟且整除一小时，边界无法与已确认采样节奏对齐时返回错误，避免插值。比较窗口按当前月初到当地小时截止，去年取同月、同日同一当地钟点。闰日缺失时取目标月末并标记截止不一致，夏令时缺失钟点返回错误。跨度、样本不完整或可比条件不满足时返回实际窗口和质量，完整同长可比时才计算差值，基期为零时无百分比。

## 实现边界

`contracts.go` 定义目录、身份、授权、量测接口，契约测试在内存验证调用顺序和授权。调用方完成授权后，可用 `CalculateFromSource` 加载点位。它将准确的点位、时间窗与能见截止传给来源，并拒绝返回错点。保留原有隔离预览响应，以同一 Go 计算服务换算样本。`usage.go` 逐期保留来源和质量，`calendar.go` 处理时区及同期，`units.go` 负责物理量归一与受控折标。计算函数无数据库和 HTTP 依赖。存储物化、权限接线和真实来源接入留待契约所有者确认。
