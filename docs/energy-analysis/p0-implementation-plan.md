# P0 开发实施计划

依据 PRD 附录 A，本期验收 10 项：F01–F04、F06–F09、F11、F21。共享能力优先，依次验证单项目、单能源统计，扩展多维口径与对比，再接页面和报表。沿用 Go 服务、PostgreSQL 迁移体系、现有管理 API/React 路由和 UI 组件。计划中的表、接口和页面是拟议设计，最终契约随主数据和权限评审定稿。 [现状审计](current-state.md) · [功能差距](feature-gap-matrix.md)

## 1. 前置契约与职责

| 需确认事项 | 交付责任 | 验收证据 |
| --- | --- | --- |
| 身份、权限和项目目录 | 平台负责人提供可信主体、租户/项目 ID、角色和项目/对象授权来源；能耗实现项目和行范围检查。 | 在隔离测试环境有两个项目、至少两种权限的测试身份。项目 ID 来自经核验的身份范围，客户端参数用于选择授权范围。随下载权限变更重新判权。 |
| 建筑、空间、组织 | 业务/主数据负责人提供稳定 ID、层级、有效期、项目时区、面积定义与字段来源。能耗消费并维护计量映射。 | 至少一组包含建筑、楼层、区域、科室和一次归属变更的样本。扩展统计维度的目录、范围和所有者已定义。 |
| 计量和数据读取 | 设备接入及快照负责人确认 `terminal.id + item_code`、累计/区间/瞬时类型、单位/倍率、换表/复位、采样期望与可读历史。若已有统一间隔量优先读取。 | 至少包含电、水、总表和分表、晚到、重复和换表样本。记录来源、覆盖、时间语义和可追溯键。 |
| 能耗定义和指标 | 能耗与项目业务方确认分类分项字典、折标审批、物理计量边界、分配规则、面积/人数取值期和合格数据门槛。 | 带原始数据、单位及生效版本的手工核算样本。相同数据、倍率与边界下，和手算差异不超过 0.5%。 |
| 报表运行与试点预览 | 能耗负责人和平台负责人确认报告快照、文件有权访问方式、保留期限及现有测试预览入口。 | 同一过滤条件下页面与 Excel/PDF 可核对；预览使用隔离测试数据与明确授权的测试对象。 |

若上游缺少确认的项目权限或主数据，先使用隔离样本与源适配器验算。正式试点启用以共享契约和授权贯通为条件。本地单层建筑/区域草案可用于核对交互，历史绑定须由统一稳定 ID 和版本表达。

## 2. 数据库调整建议

优先用能够核实来源的共享目录和表计数据，只在能耗侧新增映射、计算结果和报告。建议以 `(tenant_id, project_id)` 为作用域，项目时区取可信目录；对目录对象和点位的引用使用稳定外部 ID，同库时可用复合外键。版本和有效期用 `[valid_from, valid_to)`，保留创建/审核主体、时间和原因。下表不分配迁移编号。

| P0 逻辑对象 | 字段、约束及复用 |
| --- | --- |
| 建筑/空间/组织目录和点位引用 | 共享目录提供 `building_id/spatial_node_id/org_unit_id`、父节点、类型和时区。点位关联 `terminal.id + thing_model_property.item_code` 或上游 `meter_id/channel_id`；记录能源、标准单位、量测类型、倍率、时区来源和有效期。上游提供哪项就读取哪项，缺少的已审核能耗语义可附加在能耗点位配置。 |
| `energy_category`、`energy_conversion_factor` | 项目分类分项树，含能源类型、父节点、预置模板来源和版本。单位/折标系数区分换算类型，含来源、生效区间、单位对、版本与审核状态。物理量取规范单位，水独立展示，折标只用适用版本。 |
| `energy_point_binding` | `point_ref, dimension_type, dimension_id, category_id, scope/boundary_id, role, weight, effective_range, version`。同一视角校验重叠与权重总和；明确剩余比例为未分配。同一查询树按点位与区间去重，所有历史替换保留旧版本。 |
| `meter_balance_edge` | `boundary_id, parent_point_id, child_point_id, energy_type, effective_range, version`。约束同项目、同量纲、不可自连；按有效期拒绝循环和同边界同一子点位的多父重叠。跨边校验需事务内按边界串行写入，防并发成环。 |
| 区间用量与修正 | 优先读上游 `meter_interval` 或以 RAW/快照端点计算。用量输出 `point, interval_start/end, usage, unit, quality, source_refs, rule_version`。若已有经审核的修正来源，消费其版本；否则新增能耗修正记录保存区间、理由、审批与原样本引用。原始值、采集和快照保持由源系统管理。 |
| `energy_aggregate`（时/日/月） | 键含项目、同视角合法边界/对象、分项、能源/单位、粒度、桶起止、规则版本和结果代次；存用量、期望/有效样本或区间计数、质量、水位与追溯引用。按项目时间桶做限定影响范围的幂等重算，受影响归属/修正进入重算队列。事务完成后切换可见代次，旧报表引用既有代次或固化数据。先在样本覆盖时/日/月，审核后再扩围。 |
| `metric_definition`、`business_driver_value` | P0 固定单位面积、人均定义，保留公式版本、单位和分母来源、生效范围、周期、质量。分母优先读建筑目录、人员聚合服务；若经业务方授权录入，保存审批与来源，粒度不足时返回原因。公式仅执行白名单数字运算。 |
| `report_template`、`report_run` | P0 固定综合/分类分项模板版本。任务保存已核验的请求范围、项目时区、时间窗及覆盖率、输入/归属/系数/计算版本、审计主体、状态、文件引用和校验和。生成结果固定数据切面；重试使用同一任务幂等键，下载时再验权。 |

定额、目标、考核、行业公式包、诊断、改造和 M&V 表待 P1/P2 确认并按版本增补。能耗结果与现有快照、计费数据保持独立所有权。

实施时先提交小份契约和候选 DDL，检查旧 schema 兼容性、回填规模、锁持有、权限和回滚。GitHub 基线末尾迁移为 `0024`，原工作区另有草稿 `0025`，正式编号待协作者同步。经审核后在可恢复隔离测试库执行迁移，先启用影子统计，比较样本和旧接口。应用层可停用新入口和物化工作，保留历史结果供核对，关联数据的清理或结构回退单独评审。

## 3. P0 API 接口清单

下表路径均相对于现有 `/admin/v1/analytics`。建议使用 `/building-energy` 子路径建立受控新契约，旧查询调用者仍可走原入口，经批准后可通过既有网关对接 PRD 提议的外部前缀。响应复用现有管理外壳和列表分页。所有接口以已验证的主体和项目权限为基础，权限过滤先于聚合、排名、细查与导出。开发阶段用同一个条件模型进入 Go 聚合服务及报表。

| 方法和路径 | 用途与关联 | 附加输入 / 返回字段 |
| --- | --- | --- |
| GET `/building-energy/dimensions` | 共享筛选、F03/F07 | 项目、视角、父节点、关键字 → 授权内建筑/楼层/区域/组织/扩展维度节点和有效范围。 |
| GET `/building-energy/categories` | 分类分项树、F01/F02/F06 | 能源、版本或日期 → 授权项目的能源种类、分项、单位、来源。若有可信共享字典，可在此读透。 |
| GET `/building-energy/points` | 映射编辑、分析下钻 | 风险受控的点位分页、名称/能源筛选 → 点位和量测口径、可见范围、数据可用性。 |
| GET/POST `/building-energy/bindings`；PATCH `/building-energy/bindings/{id}` | F03/F06/F07 可查可配归属 | 点位、视角、分类、权重、边界、有效期、版本及变更原因。并发冲突返回 409；关闭关系采用版本化终止。 |
| GET `/building-energy/overview` | F01–F04 | 卡片、分类组成、区域排名摘要、趋势和最近区间；折标版本与可计算状态。 |
| GET `/building-energy/statistics` | F06/F07、F21 报表预览与下钻 | `group_by`、分项、明细/汇总维度、排序分页 → 行、总量、有效粒度、统计数据版本与导出同一查询切面。 |
| GET `/building-energy/comparisons` | F04/F08 | 同比/环比、自然完整周期/同期至当前 → 两边实际区间、持续时间、基期/本期、差值、变化率、趋势和可比状态。 |
| GET/POST `/building-energy/balance/edges`；PATCH `/building-energy/balance/edges/{id}` | F09 拓扑读取与审核配置 | 统计边界、父点/子点、有效期、版本、原因；校验能源、作用域、循环和重叠。 |
| GET `/building-energy/balance` | F09 能流/差额 | 边界和所选父点 → 父值、子值、预期子点与覆盖、差额/比例、数据来源与图边节点。 |
| GET `/building-energy/indicators` | F11 | 指标编码、范围、周期 → 分子、分母、结果/单位、来源、公式版本、质量和不可计算原因。 |
| GET `/building-energy/reports/templates` | F21 模板列表 | 综合/分类分项 → 模板版本、可用格式、可见字段。 |
| POST `/building-energy/reports/jobs` | F21 生成 | 模板、格式、查询快照或同一筛选、幂等键 → 任务 ID / 状态。综合 Excel/PDF，分类分项 Excel。 |
| GET `/building-energy/reports/jobs`、`/building-energy/reports/jobs/{id}`、`/building-energy/reports/jobs/{id}/file` | F21 列表、状态、文件 | 分页、任务和文件读取，返回授权后的状态、关联快照 ID、失败原因或下载响应。 |

公共查询参数建议承袭 UI/后端的命名约定，使用 `project_id, building_ids, spatial_ids, org_ids, dimension_type/ids, energy_type, category_ids, from, to, granularity` 和现有 `page/pageSize`。起止为 RFC 3339，后端按项目 IANA 时区解释自然周期。响应需要有授权范围、实际桶区间及有效粒度、能源单位、质量计数/覆盖、最后样本/统计区间和可追溯版本。对数据为空、部分覆盖、可用性缺失分别提供状态；定义已知零、无分母、基准零、未确认倍率和来源未支持等业务状态。范围越权返回 403 或在资源层按平台惯例返回 404。审核权限按配置类型细分，导出必须校验报表及其明细的当前对象授权。父表值、跨对象合计和残差也可能暴露受限分项。只有具备整个平衡边界的查看权限才返回该边界的完整结果。

对外部依赖先定义读取契约和使用方测试：项目/建筑/空间/组织目录、主体授权范围、点位/间隔量或原始读取、面积/人数聚合，以及未来的参考费率。上游若提供已有客户端，在现有服务内复用。P1/P2 再确定叠加的 `/benchmarks`、`/targets`、`/assessments/run`、`/diagnostics`、`/retrofits/{id}/baseline`、`/retrofits/{id}/verify`、行业模板和报表类型，沿用同一合同和鉴权。

## 4. 前端页面结构

为沿用现有框架，将 PRD 建议的一级入口落为现有一级“分析”分组下的“建筑能耗监测分析”模块，使用 `/ui/a/energy` 和五个标签页。复用 `AppShell`、`FilterBar`、`RelationSelect`、`DataTable`、分页、抽屉和状态组件。按需显示项目、建筑/空间、组织、能源、时间及粒度；URL 保存共享查询，切换标签页复用适用条件。空数据、无权限、迟到数据、部分覆盖、加载与错误均有明确状态。旧路由保留兼容，新模块逐步接入。

| 标签页 / 建议后缀 | P0 内容与主要交互 |
| --- | --- |
| 能耗总览 `/overview` | F01 卡片分能源和综合折标，F02 分类构成，F03 分区分项切换并下钻，F04 历史/最近已收到区间、刷新和覆盖。 |
| 能耗统计分析 `/statistics` | F06 分类分项树/明细，F07 切换空间/组织/扩展视角；F08 同环比、趋势与排名，F09 物理能流和平衡抽屉。获得权限的用户可进入归属或总分表配置。 |
| 能效指标与考核 `/indicators` | F11 面积/人均指标，显示单位、分子、分母、质量与来源。P1 启用行业模板、定额、目标与考核。 |
| 节能诊断与改造评估 `/diagnostics` | 保留导航及路由规划，P1 首次具备诊断能力时启用，P2 增加改造评估。P0 只在现有观测入口保留对应数据质量排查。 |
| 能耗报表 `/reports` | F21 综合/分类分项切换、筛选预览、分页明细、导出、生成状态与历史文件；配置相同范围及版本即可核对。 |

## 5. 实施任务与验收顺序

| 顺序 / 实施任务 | 负责人角色 / 依赖 | 可验收交付 |
| --- | --- | --- |
| M0 权限与契约门槛 | 平台、业务、设备接入、快照和能耗共同确认 | 冻结对象 ID、主体与授权来源、计量语义和验收样本；补上项目内所有点位与访问用例。与主数据和设备所有者确认本地归属草案处理。 |
| M1-A 计量区间、质量和物化 | 能耗后端，输入来自设备接入、快照 | CALC-01/05/06/11/12。对累计表做端点差值、重置分段与倍率；区间数据归桶；用水量单列，精度和覆盖明确；提供时/日/月结果、水位和可追溯重算。 |
| M1-B F07 多维统计 | 后端与前端，依赖 M0/M1-A | 授权目录+有效期映射+读写、同视角去重和跨期分配；原归属可追溯。 |
| M1-C F06 分类分项统计 | 后端与前端，依赖 M1-A/B | 项目字典与分项表，下钻能追到点位、单位和质量；合计校验。 |
| M2-A F09 能流与总分表平衡 | 后端与前端，依赖 M1 | 确认独立物理边界并有向校验，输出对齐的父/子、差额与覆盖；父表优先作为该边界的汇总计量依据。 |
| M2-B F08 同环比/趋势/排名 | 后端与前端，依赖 M1，正式总量依赖 M2-A | 自然日历与同期截止，明确可比口径与差异原因，排行提供同维度和质量上下文。 |
| M3-A F01 综合能耗概览 | 趋势/总览开发，依赖 M1/M2-A | 分能源多卡片，范围合计与换算证据；综合能耗仅用已审核适用的系数。 |
| M3-B F02 分类构成 | 总览开发，依赖 F01/F06 | 以同一能源单位或经审核的折标量作百分比，区分缺失与零。 |
| M3-C F03 分区分项概览 | 总览开发，依赖 F06/F07/F09 | 按建筑、区域、组织可预览、切换、下钻，筛选条件跨标签页连贯。 |
| M3-D F04 实时/历史趋势 | 趋势开发，依赖 M1-A/F08 | 使用项目时区的趋势、可解释缺口和最后统计区间，晚到时触发指定范围重算。 |
| M4-A F11 通用能效强度 | 能耗及业务数据负责人，依赖 F06/F07、M0 分母 | 单位面积、人均两类后端指标；分母缺失、零、不同范围/跨期时有不可计算原因。 |
| M4-B F21 综合与分类分项报表 | 能耗、平台和测试，依赖 F01/F06/F07/F08 | 预览与 Excel/PDF 同源；后台任务、下载时授权、审计和历史版本。整体验收后可交付隔离预览。 |

M2–M4 的共有口径为 `[from, to)` 桶归属、独立定义累计端点/前值、项目自然周期、父子边界避免双计、统一覆盖率和版本。未确认的负跳量保留为断段及待确认状态。父表不可用或分项缺失时说明当前可见覆盖，差额以“未分配/待核查”展示，仅在父值大于零且两侧可比时计算差额率。同比或环比跨度不等时显示区间与时长并明确计算方式。

## 6. 测试用例

先用固定输入的 Go 计算测试覆盖单位、归属、权限和周期，再在经审核的隔离数据库做迁移、鉴权、历史、任务与 API 集成验证，随后通过 React 页面和真实导出核对。以下 PRD AT 编号保留，跨版本用例分阶段验收。

| ID / 阶段 | 输入或操作 | 预期 |
| --- | --- | --- |
| AT-01 / P0 | 电表累计 1000 → 1040 kWh，倍率 1；再测已审核倍率 2。 | 用量分别为 40 和 80 kWh，能回溯两个端点和倍率。 |
| AT-02 / P0 | 总表 100，子表 70 和 20；另测父值 0、子值超父值及一个子表缺失。 | 总量 100，差额 10、差额率 10%；父值为零时比率为空，负差额待核查，缺子表显示覆盖及原因。 |
| AT-03 / P0 | 换表、已知回卷、未确认负跳、晚到/重复。 | 已确认回卷按量程计算，换表分段，未知负跳留断段，重算无重复累计，记录历史版本。 |
| AT-04 / P0 数据门槛、P1 考核 | 期望 100、有效 70；分别构造真实零与无数据。 | 70% 和缺口可见；零与无数据可区分；正式考核不可用。 |
| AT-05 / P0 | 电 kWh、水 m³、热 GJ，分别有/无有效折标。 | 原单位分列，水单列；综合折标按有效版本生成，转化条件不足时给出原因。 |
| AT-06 / P0 | 当月 15 日本地时点同比；另测月末、闰日和夏令时 23/25 小时自然日。 | 去年同一自然周期按同期截止规则比较；覆盖、长度和实际范围可见；相邻桶无重复边界，基期为零时变化率不可算。 |
| AT-07 / P1，P0 覆盖分子分母机制 | 年耗 1500 tce、收入 50000 万元；P0 用面积/人数验证有效、零、缺失、跨期。 | 行业指标 0.0300 tce/万元且显示来源；P0 合法才计算，其他状态有可查原因。 |
