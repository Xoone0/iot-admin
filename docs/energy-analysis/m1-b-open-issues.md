# M1-B 开放事项与进入条件

**允许进入设计评审和候选 DDL 评审。数据库实施尚无 Go 条件。**

| 优先 | 待核实事项 | 负责人角色 | 可关闭的证据 |
| --- | --- | --- | --- |
| 阻塞 | 项目、建筑、空间和组织的权威目录、稳定键、时区版本及组织历史。 | 平台/建筑/组织负责人 | 提供接口、稳定 ID 样例、版本和目录有效期规则。确认旧本地建筑区域草案如何兼容。 |
| 阻塞 | 可信身份来源及项目、对象、点位权限。发布权限需覆盖旧、新目标，历史查询、导出和下载需要独立动作。 | 平台鉴权负责人 | 签认主体和授权矩阵，在隔离环境用两个项目、局部权用户、撤权案例验证。现有 `AllowAll` 不满足。 |
| 阻塞 | 物理表/通道、累计与区间量、倍率、模数、采样节奏、换表、复位与代次的权威来源。 | 设备接入与快照负责人 | 样本对账能解释各源字段和 time/revision，节点、属性、量测语义和生效时间可追溯。 |
| 阻塞 | 候选结构、版本保留、归属变更审批、迁移/回填与恢复方案。 | 能耗维护者与数据库负责人 | 审核 DDL 与 CAS，确认扩展资格、索引/锁方案、历史背填范围和隔离数据库。 |
| 功能门槛 | 原子目录目标及聚合父子关系，物理父子表边界。 | 业务目录负责人、设备拓扑负责人 | 分别验证目录树去重和物理不重叠计量边界。核对上层总表及子表汇总边界。 |
| 功能门槛 | 数据截面、重算代次切换、历史报表重放和数据质量控制。 | 能耗与数据平台 | 通过数据库事务并发、幂等重跑、回滚、样本对账与保留策略验证。 |
| UI 交付门槛 | 五页实际权限和报表路径、上下文筛选、完整对比度和无障碍。 | 前端/产品/测试 | 在有权限模型的试点页面和可用数据截面复测。当前截图只覆盖隔离样本。 |

当前代码证明内存约束、权限调用顺序和 CAS 端口行为。真实约束、上游契约和集成测试仍需单独签认。 [设计评审](m1-b-design-review.md) · [接口契约](m1-b-contracts.md)
