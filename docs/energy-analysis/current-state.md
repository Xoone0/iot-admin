# 建筑能耗监测分析架构审计

审计基线为 GitHub `Xoone0/iot-admin` 的 `dev` 提交 `2563cd3`。功能与验收口径取自《建筑能耗监测分析模块 PRD V1.0》第 4–13 节及附录 A。PRD 的建议 API、表名、部署流程属于设计输入。本轮授权范围由用户消息确定，为仓库审计、实施规划和本地分支创建。 [GitHub 基线](https://github.com/Xoone0/iot-admin/tree/2563cd367bcd333d85a650f1be441f3f9589dcaa) · [PRD 校验信息](HANDOFF.md#需求基线)

## 结论与开工条件

仓库可以复用终端档案、物模型、采集链路、快照和 React 管理端。当前分析是以终端、变量和存储时段为主的数据查询。P0 首先需要确认建筑、空间、组织及项目的权威来源，补齐计量口径和有效归属，并接入可信的项目/对象级授权。先用固定样本贯通单项目、单能源用量和权限，再扩展多维统计、能流和报表。

25 项中，已实现 **0** 项，部分实现 **14** 项，可复用平台能力 **1** 项，未实现 **10** 项。10 项 P0 都有可演进的现有界面或查询。判定标准和逐项证据见[功能差距矩阵](feature-gap-matrix.md)。现有查询在可信样本上能展示用量，尚无证据支持按项目权限和计量边界交付正式统计。

## 1. 现有运行与数据结构

| 层面 | GitHub 基线结构 | 对能耗模块的意义 |
| --- | --- | --- |
| 服务与存储 | Go `net/http.ServeMux`，PostgreSQL/pgx。进程启动连接 DB、执行嵌入迁移，再挂载管理 API、采集入口与嵌入式 `/ui`。 | 沿用同一服务、迁移体系和前端构建链路。含待审查迁移的构建在启动时会执行迁移，开发验证须使用明确授权的隔离测试库。 |
| 建筑、空间、组织 | 已提交源码与迁移中未发现项目、建筑、楼层/区域或组织/科室主数据与父子关系；运营端独立系统是否已提供这些能力尚未核验。 | `data_domain` 是数据分类，`gateway_id` 是接入归属。建筑与组织需由权威主数据或经确认的共享目录提供稳定 ID，空间树与组织树各自维护。 |
| 表计与元数据 | `data_domain → device_type → thing_model_property` 定义分类、型号与属性。 `terminal.id` 是上报终端编码，关联型号和网关，另有启停、在线、最近活跃和软删除。属性有编码、单位、值类型、精度和范围等。 | 复用终端/属性归档。能耗需要确认哪一属性为累计量、区间量或瞬时量，以及能源、单位、倍率、量程、计量边界和有效期。一个终端可能有多个能耗点。 |
| 接入与质量 | MQTT `iot/ingest/+` 与 HTTP `POST /ingest/v1/messages` 进入同一管道。校验、清洗、落原始明细、更新最新值、写快照和记录异常，质量由位标记和原因表示。 | `raw_message/raw_item` 提供接收时间、值时间、值、单位、状态和质量溯源。能耗判断需保留来源与状态，区间归桶按受认可的业务事件时间。 |
| 原始与最新值 | RAW 按接收时间分区，有保留策略。 `latest_value` 按终端与属性保存最新样本，并按值时间保护倒序写入。 | 查询历史前需核实覆盖期、晚到和重复记录策略。最新值可佐证数据新鲜度，历史用量必须由区间数据计算。 |
| 快照 | `snapshot_slot_config` 控制粒度，`snapshot_binding` 按型号/终端与属性决定入快照；`snapshot_coarse` 保存时、日、月、年分段样本。 `0017` 移除独立秒表，`0024` 移除分钟快照表与配置。 | 复用已有快照样本读取与配置入口。快照记录的是段内样本，须按已确认的属性口径和端点规则换算用量；能耗自己的统计结果另存。 |
| 权限 | `Permission.Allow(ctx, r)` 是管理 API 拦截入口。当前主进程调用 `admin.WithAuth(nil, ...)`，默认 `AllowAll`；未发现应用内租户、项目和行级权限结构。网关凭证用于上报接入。 | 独立校验可信用户与租户/项目/对象关系，贯穿选项、统计、追溯、配置、报表和文件服务。上游身份系统及反向代理策略待所有者确认。 |
| 前端 | React/TypeScript/Vite，现有导航按业务、快照、分析、观测组织。使用已有 `AppShell`、`/ui` 路由、API 客户端、表格筛选、分页与空态组件。 | 在现有“分析”内提供建筑能耗入口，共用 UI 样式和组件。原分析页可渐进迁移，业务、快照、观测由各自负责人维护。 |

## 2. API 与统计口径

管理实体现有 `/admin/v1` 前缀，常规列表支持 `filter.<字段>[.<操作符>]`、`page/pageSize`，部分快照/原始数据查询支持游标。使用现有 `code/message/data/meta` 响应外壳。可复用 `/_meta`、`/data-domains`、`/thing-models`、`/thing-model-properties`、`/terminals`、`/gateways`、`/snapshot-query`、`/raw-items` 及相应只读与异常入口；能耗 UI 的点位和范围选项仍须经过项目权限校验。 [管理路由与响应](../../internal/admin/admin.go#L450) · [列表参数](../../internal/admin/query.go#L15) · [前端 API 客户端](../../web/src/api/client.ts#L11)

| 已有 GET | 当前能力 | P0 差距 |
| --- | --- | --- |
| `/admin/v1/analytics/overview` | 总览、分类构成、分项、聚合趋势、桑基图。主要计量属性和折标依赖名称/编码/单位规则；桑基流向来自分类、型号和网关链条。 | 需显式点位语义和有效期、项目筛选、覆盖率、审核系数、可靠的项目总量和总分表边界。 |
| `/admin/v1/analytics/series` | 按型号、属性、表计查原始/快照趋势；提供读数/增量、聚合、排行、同环比。最多 20 台终端和 5000 个点的实现限制约束细查。 | 当前窗口包含两端，原始窗口用接收时间；环比按等长跨度回退，聚合对比按桶索引对齐。需事件时间、自然周期、统一端点样本规则和截断提示。表码负跳当前记回退并把当次增量归零，需按复位/回卷/换表规则分段。 |
| `/admin/v1/analytics/anomalies` | 用量阈值、跳变、非工作时段、表码回退以及按选定总/分表计算差额。 | 可复用事件和界面展示。正式平衡需要版本化拓扑和同口径证据；异常归因是 P1，并与现有质量/告警职责对接。 |
| `/admin/v1/analytics/quality`、`/health` | RAW 状态、异常汇总、网关/终端健康，支撑排查。 | 只读消费质量和状态。能耗页面补统计范围的期望点位/区间、覆盖率、最近区间与原因链接。 |

前端现有 `/ui/a/overview`、`/ui/a/trends`、`/ui/a/quality`、`/ui/a/health`。总览/趋势有客户端 CSV，部分对账表在页面只显示前 24 个时隙。面积、人数、单价和目标有页面输入或默认值，缺少版本和依据。审计建议保留用于本地看样本的查询路径，P0 正式指标和报表改用同一后端口径。 [总览计算](../../internal/admin/analytics.go#L1159) · [趋势与对比](../../internal/admin/analytics.go#L666) · [异常诊断](../../internal/admin/analytics.go#L1880) · [React 路由](../../web/src/App.tsx#L59) · [趋势与 CSV](../../web/src/pages/AnalyticsTrendsPage.tsx#L255)

时间语义还需处理 DB 会话与快照计算固定在上海时区、部分前端使用浏览器时区，以及 RAW 初始分区按 DB 日历、运行维护按固定 24 小时截断的差异。能耗按项目 IANA 时区计算自然周期，并在测试库验证采集边界；RAW 分区和保留行为由采集负责人核验。 [数据库会话](../../internal/store/db.go#L15) · [快照日历](../../internal/snapshot/snapshot.go#L137) · [RAW 分区维护](../../internal/raw/store.go#L97)

## 3. 模块冲突与归属

| 边界 | 相关功能 | 冲突及约定 |
| --- | --- | --- |
| 电力监测 / 冷热计量 | F01、F04、F06、F09、F10、F17 | 本模块消费电量与经标定的冷热量、计算用量趋势和总分表平衡。电压、电流、频率、谐波、功率因数、电能质量告警与设备诊断由专业模块负责。COP 需要同时取得同边界冷热量与电量。 |
| 设备接入 / 业务配置 | F01、F04、F06、F07、F09、F10 | 网关协议、串口、采集配置、终端档案、质量规则各由现有入口维护。能耗维护点位映射，读取倍率、换表、量程与时间口径；需要源数据时先确认接口所有者。 |
| 快照 / 观测 | F04、F06、F08、F10、F16、F17、F21 | 使用共享 RAW、快照和异常结果。能耗物化产物与快照存储职责分开；同一采集质量异常保留上游事件 ID，避免重复告警或双重确认。 |
| 计费 / 分时价格 | F08、F17、F19、F21、F24 | 用量对账、分时统计与节能情景可读经授权的费率版本，正式价格、计费规则、账单和结算由其所有者管理。仓库的分时估算 UI 不具备账本和审核语义。P0 报表以用量为准。 |
| 空间、组织与平台鉴权 | F01–F25，重点 F03、F07、F11、F15、F21、F23 | 主数据只消费授权范围，映射另存历史有效期；组织调整可重放旧口径。跨组织点位分摊、项目时区、下载授权须在共同契约中确认。 |
| 楼控 / 改造 / 碳核算 | F13、F17–F20、F24 | 楼控仅提供所需的观测数据。定额、折标和改造因子需要来源与生效版本，能耗页面可展示可核实依据；楼控写入、工程审批和正式碳盘查由其他系统负责。 |

## 4. 本地差异与验证范围

- 原工作区本地已有 UI 调整、归属、趋势与对账改动，保留在原 `dev` 工作区。本地草稿 `0025_energy_locations.sql` 为建筑、单层区域和每终端唯一当前位置，缺少项目/组织、点位属性、多视角和有效期。它可以帮助验证交互与字段，未计入 GitHub 功能覆盖率。评审先决定主数据所有权与历史绑定方案，再决定草稿的前向兼容办法。
- 审计分支 `feature/energy-analysis-prd-v1` 从上述 GitHub 提交创建于独立 worktree。本轮产物为本地审计文档和实施计划，迁移仅列建议，供后续审核。
- 基线 `go test ./... -count=1` 在清空数据库和测试 DSN 的进程中通过；依赖 PostgreSQL 的集成测试跳过。外部接口、真实采集数据、数据库迁移、部署状态与浏览器行为未在本轮验证。
