# M1-B 点位口径与多维归属契约

此契约沿用 [M0](m0-contract.md) 的 `ProjectKey`、`PointRef`、`ObjectKey`、`VersionMeta`、`Scope` 与半开区间。Go 实现位于 [mapping.go](../../internal/buildingenergy/mapping.go)，持久表仅为 [候选设计](m1-b-design-review.md)。

## 读取与映射

- `MappingTimeline` 是一个点位、一个正整数配置代次的完整配置。它包含零个或多个满足有效期约束的 `ProfileRevision` 和 `BindingRevision`。口径版本携带 M1-A `PointProfile`、物理通道来源及适用的表码代次。
- 口径版本及归属集合使用 `[from,to)`，右端可开放。一个点位同一时刻只有一个口径。在每个视角中同一时刻只有一个归属集合。建筑、空间和组织独立查询。禁止将三种视角的总量相加。
- 归属使用整数百万分率。单项须大于零且不超过 1,000,000，集合总额不超过 1,000,000。多个目标应为同视角不重叠的原子对象，由上游目录校验父子关系、别名和后代展开。查询汇总使用去重后的目标集合。未分配份额保留在已授权的完整映射中。
- `Resolve` 为一段已对齐的统计区间取得单个口径与当前视角的集合。相邻版本可在边界接续。跨生效点的原子区间返回待拆分/核查错误，口径空窗返回缺配置，无映射集合时保留全部未分配。M1-A 值与质量由计算器提供，映射权益不改变 `Expected/Valid/Missing/Suspect`。
- `ReadAuthorizedMapping` 使用 M0 的 `ResolveScope` 校验项目、点位以及显式对象，授权后调用 `MappingReader.ReadMapping`。适配器必须返回请求的点位和精确代次。全部活跃分配目标都在显式授权范围内时才返回完整映射和残差。只授权部分对象时，当前完整映射读口拒绝访问，未来的局部统计由授权后独立聚合并隐藏其他对象及其推导值。
- 分类、扩展视角和物理边界留有 schema 扩展位置，本轮 Go 只接受建筑、空间及组织。 `ValidateBoundaryContributors` 校验已由拓扑提供者归组的同一边界内，父级总表与该总表覆盖的分表不能混选，清单内点位须在同项目且无重复。它不解析设备拓扑。独立拓扑确认前，分区树结构不可作为物理表网的证明。

## 发布和并发

- `PublishMapping` 从 `IdentitySource` 取得可信主体，并要求 `MappingChangePolicy` 对期望代次、变更和审批证据授权。适配器必须检查 `ManageBindings`、旧目标、新目标、点位及全部生效区间。无可信主体或策略时拒绝。写入端口 `MappingWriter.CompareAndSwapMapping` 只接收通过检查的候选及同一期望代次。正式写入入口、权限适配器和仓库还需实现及评审。
- 期望代次 0 表示首发，候选代次应为期望值加一。审批记录包含可信签发方/主体、提交时刻和原因。仓库须在同一事务检查当前代次、追加新/旧代次审计、保存候选并更新头指针。冲突返回 `ErrMappingConflict`，客户端重新加载。禁止将冲突重试改成无条件覆盖。
- 更改历史归属按审批追加新配置代次。按原代次读取可复现已固定的报告。按新代次重算历史与未来给出修正值和依据。完整覆盖与历史快照一致性由后续持久化集成验证。
